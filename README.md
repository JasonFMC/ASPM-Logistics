# ASPM Workshop

父级平台。当前子板块：Tickets、YARD。

## 技术栈

- Vite + React + TypeScript（Hash 路由）
- YARD 用自绘底图（无 GPS）
- Supabase Sydney（Auth / Postgres / Storage）
- GitHub Pages 托管

## 本地启动

1. 安装依赖：`npm install`
2. 复制环境变量：`copy .env.example .env`（Windows）并填入 Supabase URL / anon key
3. 在 Supabase SQL Editor 执行 `supabase/schema.sql`（工单另执行 `supabase/tickets.sql`，同事再执行 `supabase/staff.sql`，然后执行 `supabase/ticket_ops.sql`，再执行 `supabase/ticket_messages.sql`）
4. Authentication → Users 创建至少一个登录账号（建议关闭公开注册）
5. `npm run dev`

## 新同事第一次使用

这一节是同事启用时的现行步骤。后面的更新改完后，以这里的最终做法为准。

1. Supabase → Authentication → Users → Add user → Create new user。填可以登录平台的谷歌邮箱和密码，勾上 Auto Confirm User。这是大门，不是收信的 warehouse 邮箱。公开注册保持关闭。新建账号默认不是管理员。
2. 用这只谷歌邮箱登录后，打开工单。这一页是登录领取人：屏幕上是这只邮箱已经注册的人，头像下面是名字。点自己的头像，输入当时设的密码进入。新同事点「加入团队」，填名字和密码；左侧选一张现成小脸，右侧可以自己调脸、眼睛、耳朵、嘴巴、背景和颜色。密码不要告诉共用这只邮箱的人。进入后，筛选从左到右是未分配、处理中、等待、确认完成，最后是全部。未分配是还没分给同事的新任务，按邮件日期分开，拖到自己身上或点「领取任务」。处理中是已经领取的。等待上会标出原因。确认完成是办完的。打开一张单，里面按时间列出每一封信，每封显示新写的内容；正文里和这张工单更早的信重复的那一段，收成一行「引用了上一封」；引用了对不上的别人的信，用浅色字放进同一个边框，并写上对方名字，这段署名只留姓名，旁边是一个写成 signature 字样的图标。附件跟在这一条下面，点开仍从原信里取。电子签名不留在附件里。署名只留下姓名。信件末尾只要出现电话、网址、邮箱、公司、路名或免责声明中的任何一项，都收成签名。图片编号不显示；点这个图标展开署名：有图就显示图，没有图就显示从正文拿掉的那段署名。图只留在这一页。图在原信正文的哪一段，图片链接就排在气泡里的同一段，不看文件名。没有出现在正文里的附件，才出现在这封信的开头。写在发件人姓名之后的图，以及 logo、电话、邮箱这类小图标，才算署名图。也可以写下单号、数量和约定时间并确认，对上院子里的货或位置，标成等待时要选原因，也可以写备注。保存后的备注出现在消息前面，写着是谁、什么时候写的。备注不改状态。套上流程以后，工单状态跟着当前环节走；领取人就是这一步的负责人，要交给别人就放回。同事栏里，自己的单子后面是「放回」；别人的单子后面是「帮助同事」。点了之后单子仍留在原同事那里，你的名字会一起出现在标题后面。再点「不帮了」就退出。右侧「任务池」旁边是「搜索」。可以按文档整理或客户名称、发件人、日期区间、标题和邮件关键字找任务，填一项或几项后，结果列在中间。关键字在标题、摘要，以及两周内还留着的原信正文里找。页面左栏上方是「客户名称」，下面是「文档整理」。名单比屏幕长时，用滚轮往下看，进度条在屏幕最左侧。两边都按客户的邮箱或域名收录。对方发来的，以及我们发给这个地址的，都会归进来，不用另填收件人。每次填一条，点加号再加一条。编辑客户名称时，发件人一行左侧是减号，用来删掉这一条，改完点这一栏的保存。点其中一个后，任务池还在，左侧原来的「未分配」换成这个名字，里面是收进来的任务。这一栏标题旁有「返回」。点「返回」，或点筛选里的「未分配」，左侧回到打开之前的未分配任务。要改收录条件时，点这一栏标题旁的「编辑」。保存或取消后回到任务池里的这一栏。进入员工身份后可以在两边分别新建。保存后，任务池里对得上的任务会收进去，也可以把任务拖到左侧对应的名字上。这些任务仍留在任务池里，标题后面会带上这个名字。编辑时可以勾选「不在未分配任务池中显示」。勾选后，收进来的任务不再出现在未分配栏目；打开该项仍能看到。不勾选时，这些任务仍留在未分配里。自动领取不再填写邮箱。在右侧同事卡片、自己的「改资料」，或管理员的「员工」页，点「自动领取」。页面里有一个客户池，里面是左侧已经建立的客户名称；被领走的客户会标上同事的名字。把客户拖进自己，对得上且还没人领的任务就记到这个人身上，只从「未分配」里拿掉。拖回客户池就取消。处理中列出已经领取的任务，也包括还在等客户回复、但已经领走的。同事名下按客户名称分组，同一个客户的任务排在一起。等待仍列出全部等待中的任务，标题后面带上领取同事。已经有人领的不会被改走。几位同事的客户都对上同一张单时，先建立的那位领到。客户不再归自己时，自动领的会回到未分配；亲手领取或管理员改派的留在原处。亲手放回的单，不会再被这个人自动领回去。确认完成的任务不再出现在同事栏和归类文件夹里。打开「确认完成」时不显示右侧同事，任务按完成日期分组，每张单写邮件时间和完成时间；标题后面保留归类名，并加上完成和当时负责的同事。完成满两年的任务会删掉，也不再出现在「全部」里。右下角点「改资料」进入自己的资料页，可以改名字、密码，也可以重选现成小脸，或调整脸、眼睛、耳朵、嘴巴、背景和颜色。留空的新密码表示不改。管理员在工单的「员工」页能看到改后的名字和密码，也可以直接给员工改密码。改完密码后，该员工要重新进入。要换领取人时点右下角「员工身份」。关掉浏览器标签后要重新输入密码。
3. 在这台 Windows 上双击 `scripts/Install-Open-In-Outlook.cmd`。窗口里出现 `Installed for this Windows user.` 即可关掉。每台电脑、每个 Windows 用户做一次。已经装过、点「打开原邮件」仍出现临时文件夹、新 Outlook 无法启动，或提示这封信没有编号时，再双击一次。打开时用的是这台电脑上已经登录仓库邮箱的经典 Outlook。不改邮箱密码。
4. 打开工单后，每分钟自动登录任务邮箱并对齐，也可以点「更新邮件」立刻对齐。进度和结果在按钮左侧的状态栏里，例如正在对齐、已对齐。正在拖任务，或光标还在输入框里时，任务列表先不换；松手或离开输入框后，再换上新结果。打开着的工单、正在填的搜索和归类设置都不会被这轮更新改掉。澳洲东部时间 2026-10-19（本周一）0 点之后收到的信，不论还在收件箱，还是已经被放进其他文件夹，都按到达时间补进工单。已发送、草稿、垃圾邮件和已删除不从这里读。已经建过的不重复。同一封信改了标题，还是这一张任务。对方回复如果标着之前那封信，或者去掉「回复」「转发」后标题一样、并且来往地址里有这个客户，会并进这张还没完成的任务。我们从这只邮箱发出去、属于这段来往的信，也会从已发送补进同一张任务。发给客户名称里这个地址、对方还没回的信，会单独成为一张任务，出现在等待里，原因是等客户。这个客户已经交给某位同事时，更新邮件后会把对得上、还没人领的任务记到这个人身上，等客户的也算，并出现在处理中和等待里这位同事下面。对方回复后，没人领取的回到未分配，已经有领取人的回到处理中。已完成的不再并入，新信另开一张。任务卡上写着有几封信。打开任务后，按时间从上到下显示每封新写的内容；对不上的引用放进同一个边框；和更早的信正文重复的那一段，收成「引用了上一封」。同一封信在邮箱里改了标题再保存，下次更新会改任务标题和摘要，并清掉这张工单的原信缓存；状态、仓库、客户和流程不变。从收件箱挪到其他文件夹的信，任务还留着。打开时先看上次记下的位置；这个位置还有这封信才打开。位置空了，就到这封信后来记下的文件夹，再按收信日期到其他文件夹对上，并把新位置写回去。只有这张任务里的每一封都确认不在这只邮箱里，才从任务池去掉，并留成一份不含原文和附件的档案，按收到时间保留两年。文件夹没搜完时不会删任务。一轮从还没记过的信里按收信时间先写最早的 40 封。每封记过的信写着自己的收信时间。每个文件夹再记下还没记过的最早一封是什么时候，下一轮从这一天的前一天接着找，已经记下的直接跳过。这个时间要等更早的信都记下之后才往后移，所以旧信不会被丢掉，写完会排到最新。还有没记过的信时，状态栏写还有新信，并写上最早一封的收信时间，下一分钟或再点一次「更新邮件」继续。已经对齐是这一轮没有再发现没记过的信。每次拉取都是重新登录，拉完就退出。打开任务看到的是按时间排好的每封新内容，以及引用里对不上的别人的信。点某一封的附件或「打开原邮件」时，才去邮箱取那一封。读信进度条会依次走过：已接到请求、已核对缓存、连上邮箱、取到信、取回正文、读完正文。整封正文缓存仍保留两周。附件不入库，每个附件按类型显示图标、文件名和大小，名字与邮件里一致。点一下就在新标签页打开，不会自动下载：PDF、图片、文本、转来的邮件直接显示。文件名没有常见后缀时，按文件内容判断，图片和 PDF 仍然直接显示；Word、Excel 等浏览器显示不了的，页面上写明原因。要存到本机时自己点下载：PDF 用阅读器自带的下载按钮，其他附件用页面右上角的「下载」。浏览器提示拦截了弹出窗口时，在地址栏右侧选始终允许本站，再点一次附件。PDF 若仍是直接下载，把浏览器设置里「下载 PDF 而不是打开」关掉。整封信超过 25 MB 时页面不拆这封信。点「打开原邮件」会按这一封上次记下的位置取出原文。这个位置还有这封信就直接打开。信已经挪到其他文件夹时，程序到新的文件夹对上这封信，把新位置写回去，再把原文交给 Outlook 打开。只存在于这台电脑、没有同步回邮箱的文件夹，取不到。浏览器第一次询问是否打开本机程序时，勾上始终允许。

## 部署到 GitHub Pages

远程仓库是 `JasonFMC/ASPM-Logistics`。

1. Settings → Pages → Source: GitHub Actions
2. 在仓库 Secrets 添加：
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. 推送 `main` 后自动构建部署
